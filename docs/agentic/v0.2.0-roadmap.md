# v0.2.0 agentic roadmap

The first useful milestone is one bounded `plan -> run -> evaluate` cycle. A
planner creates a structured CSP plan, the deterministic run manager calls
`run_csp_workflow`, and the evaluator returns either `SUCCESS`, another explicit
terminal state, or one structured retry recommendation. It is not an indefinite
autonomous research loop.

## Ticket 19 - State models and executable contracts

Implemented on `develop`: frozen typed records, strict versioned JSON parsing,
closed tool contracts, centralized low-level transitions, budget and approval
helpers, path confinement, state invariants, and a reusable canonical fixture.
No scientific adapter or agent runtime was introduced.

- implement versioned agent state, plan, decision, budget, approval, and result
  reference schemas;
- turn the documented tool envelopes into validated Python models;
- add serialization, state-transition, and schema compatibility tests;
- create the empty package structure only as needed by these models.

## Ticket 20 - Deterministic tool adapters

Implemented on `develop`: the closed four-tool registry, caller-owned execution
context, deterministic callable injection, run-root confinement, SHA-256
artifact references, typed failures, timing/provenance, state-application
helpers, a four-tool no-LLM fixture, and a real workflow-boundary integration
test. No Planner, Evaluator, Run Manager, Orchestrator, or retry loop was added.

- implement `search_crystal_db`, `run_csp`, `validate_candidate`, and
  `inspect_run` as thin wrappers over released APIs;
- enforce output-root confinement and read-only external resources;
- preserve original structured failure codes and provenance;
- defer `compare_candidates` unless a concrete evaluation need is demonstrated.

## Ticket 21 - Planner and model boundary

- implement provider-independent `AgentModel` request/response contracts;
- implement constraint-preserving plan parsing and tool selection;
- use deterministic fake model responses in default tests;
- add no production provider dependency.

## Ticket 22 - Run Manager and orchestration state machine

- execute validated tool calls deterministically;
- append decision, tool-call, result, and artifact records;
- implement approval gates, counters, terminal states, and restartable state;
- prohibit shell access and arbitrary paths.

## Ticket 23 - Evaluator and bounded repair

- derive scientific success only from deterministic results and metrics;
- implement one typed repair recommendation and its approval path;
- propagate infeasibility, missing resources, and validation failures without
  flattening their codes;
- enforce maximum workflow/retrieval/repair/wall-clock budgets.

## Ticket 24 - Agentic integration and end-to-end tests

- combine a deterministic fake model with real v0.1 tool adapters;
- test success, infeasibility, missing DB, missing POT, unavailable Gurobi/SCA,
  invalid tool choice, approval, and budget exhaustion;
- prove the non-agentic v0.1 API remains operational and unchanged;
- require no paid API or live model in the default suite.

## Ticket 25 - First real provider adapter

- add one optional provider integration behind `AgentModel`;
- keep credentials out of state and traces;
- separate provider/format failures from scientific failures;
- retain fake-model parity and a fully provider-free core install.

## Ticket 26 - Agentic benchmark and release audit

- evaluate planning correctness, tool selection, constraint preservation,
  justified retries, stopping behavior, and hallucinated-success avoidance;
- keep external-model evaluation separate from scientific correctness;
- audit packaging, licensing, external requirements, and v0.1 compatibility;
- decide whether `compare_candidates` and broader autonomy are justified for a
  later release.

Benchmark-specific action libraries and persistent long-term memory are not on
the critical v0.2 path. Either requires a separate design and evidence review.
