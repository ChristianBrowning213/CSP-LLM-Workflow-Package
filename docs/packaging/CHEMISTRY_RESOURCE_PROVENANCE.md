# Chemistry and radii resource provenance

Audit date: 2026-09-12. This inventory covers the six generated base resources
and the separate legacy radii file bundled by QLIP. No resource or scientific
implementation was changed.

## Generation record and upstream terms

QLIP's MIT-licensed `scripts/build_base_data.py` generated
`resources/base/*.json`. The embedded record names ASE 3.27.0, mendeleev
1.1.0, pymatgen 2026.5.4, and SMACT 4.0.0. Installed distribution metadata for
those exact versions reports LGPL-2.1-or-later for ASE and MIT for mendeleev,
pymatgen, and SMACT. These are software-distribution terms; they do not, by
themselves, resolve every possible right in facts compiled from the cited
scientific literature.

The generator records the Cordero covalent-radii, Pyykko covalent-radii,
Meija atomic-weight, and Shannon ionic-radii citations. It copies values
exposed by the libraries, normalizes some units to Angstrom, rounds to six
decimal places, and computes source-selection/default fields. Runtime
derivation would avoid redistributing the compiled tables but should preserve
these citations and the applicable dependency notices.

## Exact parity procedure and limits

The frozen generator was run in an isolated environment with the four versions
recorded in `base/provenance.json`. SHA-256 equality was required, not visual
similarity. `elements.json`, `radii.json`, `ionic_radii.json`, both policy files,
and every value within them matched exactly. `provenance.json` differed only in
the UTC generation timestamp and was otherwise structurally/value exact.

The installed `pymatgen==2026.5.4` distribution currently resolves its split
`pymatgen-core` dependency to 2026.8.30 and still produced exact output. A
future implementation should lock the complete resolved environment (including
transitive package versions and artifact hashes), preserve the generator and
citations, and rerun full-table parity tests before deleting bundled base
tables.

QLIP's current runtime reads `base/radii.json` plus `base/radius_policy.json`
to build the atomic-radius map used by proximity preflight/constraints.
`elements.json` and `ionic_radii.json` are exposed through the base-data
registry but are not otherwise consumed by the packaged solve path found in
this audit. Exact full-file parity nevertheless tests every present value, not
only the narrower runtime subset.

## Decision summary

- Replace later: `base/elements.json`, `base/radii.json`, and
  `base/ionic_radii.json` (`CAN_DERIVE_AT_RUNTIME`).
- Retain: `base/radius_policy.json`, `base/pair_distance_policy.json`, and
  `base/provenance.json` (`REDISTRIBUTION_RESOLVED`).
- Remove later unless provenance is supplied: legacy `resources/radii.json`
  (`BLOCKED`).

No replacement or removal occurs in this ticket.
