# LLM-CSP v0.1.0

LLM-CSP v0.1.0 is the first complete candidate for the deterministic public
crystal-structure prediction workflow.

## What v0.1.0 contains

~~~text
structured crystallographic request
        -> Crystal-DB retrieval
        -> SPP guidance preparation
        -> QLIP integer-programming CSP
        -> candidate CIF
        -> SCA validation
        -> structured provenance/result
~~~

## Supported capabilities

- Crystal-DB retrieval software
- request-specific SPP construction and external POT-library selection
- QLIP CSP solving and configured scaffold/topology constraints
- deterministic workflow execution and structured provenance
- SCA general and family/topology validation
- command-line interface and offline installation/workflow smoke test

Core installation is `pip install .`. Install supported validation with
`pip install ".[validation]"`. Production execution uses
`llm-csp run --config <config> --output <dir>`.

Supported SCA version: `0.1.1`

Supported SCA commit: `3ede1ee2ad1a972b7c0a0809a9ec7bdab9b1b6af`

## Offline smoke

Run `llm-csp demo`. No optimization is run. No scientific POT
library is bundled. The result is not a crystal prediction. The smoke performs
no network request and does not require production data, SCA, or Gurobi.

## External production requirements

- production Crystal-DB corpus/index and compatible embedding backend
- lawfully sourced POT library
- Gurobi runtime and usable licence
- optional third-party ML validation assets where explicitly requested

## Not bundled

- production CIF/database corpus, embeddings, indexes, or models
- broad POT corpus or blocked historical SrTiO3 POT assets
- third-party model weights
- agentic orchestration
- benchmark or paper campaign data

## Known limitations

Real QLIP runs require an explicit finite design space and Gurobi. Validation
beyond SCA's base general/topology path may require external ML packages and
assets. This release is the deterministic workflow; agentic orchestration is
not included.

## Release status

All distributed code and assets have a resolved licensing basis. Because real
scientific operation depends on the external requirements above, the release
classification is `READY_WITH_DOCUMENTED_EXTERNAL_REQUIREMENTS`.
